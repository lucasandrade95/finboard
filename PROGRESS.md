# Progresso

- **2026-08-28** — Endpoint GET `/api/categories?month=` devolvendo as categorias distintas já usadas (`{ categories }`), com o mesmo schema Zod de mês das outras rotas (400 se mal formatado). A ordenação é feita em JS com `localeCompare('pt-BR')` porque o `ORDER BY` do SQLite compara byte a byte e jogaria "água" depois de "transporte". No front, isso resolve uma gambiarra: as opções do filtro de categoria eram deduzidas da página de transações carregada e precisavam ser "congeladas" com um `useEffect` enquanto algum filtro estava ativo, senão o select colapsava nas categorias do recorte. Agora vêm do novo hook `useCategories` (cache por mês no TanStack Query, invalidado ao criar/editar/excluir), e o `useEffect` sumiu. O campo "Categoria" do formulário ganhou um `<datalist>` com essas mesmas categorias: sugere o que já existe sem impedir digitar uma nova, o que reduz duplicata por digitação ("mercado" vs "Mercado"). Quatro testes novos no server (distintas ordenadas, recorte por mês, lista vazia, mês inválido), um no client de API e dois de componente no formulário.

- **2026-08-27** — Busca textual por descrição: GET `/api/transactions` agora aceita `q=` (Zod, 1–100 caracteres, 400 se vazio), combinável com mês, tipo, categoria e paginação — o `total` continua refletindo o recorte inteiro. A busca usa `description LIKE '%termo%'` com os caracteres `%`, `_` e `\` escapados e cláusula `ESCAPE`, para que quem digitar "50%" procure literalmente "50%" em vez de casar com tudo (curinga do SQL); o parâmetro segue vindo por bind, então não há concatenação de SQL. Na UI, campo "Buscar" na barra de filtros com debounce de 300 ms via novo hook `useDebouncedValue`: digitar não dispara uma requisição por tecla, só uma após a pausa. Um termo novo volta para a página 1, e as opções do select de categoria continuam congeladas enquanto a busca está ativa. Cinco testes novos no server (busca sem diferenciar maiúsculas, combinação com os outros filtros, curingas tratados como literais, resultado vazio e termo vazio rejeitado), dois no client de API (URL codificada e termo vazio omitido), três de componente no campo e três no hook de debounce.

- **2026-08-25** — Filtro por tipo (receita/despesa): GET `/api/transactions` agora aceita `type=income|expense`, validado pelo mesmo enum Zod usado na criação — valor desconhecido devolve 400 em vez de lista vazia silenciosa. O filtro é combinável com mês, categoria e paginação (o `total` continua respeitando todos os filtros juntos). Na UI, novo select "Tipo" (Todos/Receitas/Despesas) ao lado do filtro de categoria; trocar o tipo volta para a página 1 e as opções do select de categoria só são recalculadas quando nenhum filtro está ativo, para a lista de categorias não encolher junto com o recorte. No client, os filtros da listagem viraram um objeto único (`{ type, category }`) em vez de parâmetros posicionais soltos, e a chave do TanStack Query usa só primitivos para o cache não invalidar a cada render. Três testes novos no server (tipo + mês, tipo + categoria, tipo inválido), dois no client de API (URL com tipo e com tipo+categoria) e quatro de componente no novo select.

- **2026-08-24** — Filtro por categoria: GET `/api/transactions` agora aceita `category=` (validado por Zod, 1–50 caracteres, 400 se vazio), combinável com mês e paginação — o repositório monta o WHERE dinamicamente com condições parametrizadas e o `total` respeita todos os filtros. Na UI, novo componente `CategoryFilter`: um select acima da tabela com "Todas" + categorias do mês; as opções congelam enquanto um filtro está ativo (para o select não colapsar na categoria escolhida) e a categoria selecionada permanece visível mesmo se sair da lista ao trocar de mês. Trocar o filtro volta para a página 1. Três testes novos no server (filtro combinado com mês, categoria sem resultados, categoria vazia rejeitada), dois no client de API (URL com paginação e categoria codificada) e quatro de componente no select.

- **2026-08-21** — Paginação na listagem: GET `/api/transactions` agora aceita `limit` (1–100, padrão 20) e `offset` (padrão 0), validados por Zod com coerção de string, e devolve `{ items, total, limit, offset }` — o `total` respeita o filtro de mês, então a UI sabe quantas páginas existem sem buscar tudo. Na tabela, controles "Anterior/Próxima" com "Página X de Y" (só aparecem quando há mais de uma página), página volta para 1 ao trocar de mês e, se a última transação de uma página for excluída, a UI recua sozinha para a última página válida. Cinco testes novos no server (fatia correta com offset, total preservado, limites rejeitados com 400) e dois de componente (navegação chama onPageChange, controles escondidos com página única).

- **2026-08-20** — Edição de transações: novo endpoint PUT `/api/transactions/:id` (substituição completa validada por Zod, 200 com o registro atualizado, 404 se não existe, 400 para payload inválido) e edição inline na tabela — o botão "Editar" transforma a linha em formulário com todos os campos preenchidos, com Salvar/Cancelar. A mutação invalida lista e resumo no TanStack Query, então os cards recalculam sozinhos. Três testes novos no server (incluindo reflexo no resumo e que payload inválido não altera nada) e dois testes de componente na lista (abrir com valores preenchidos e cancelar sem salvar).
- **2026-08-20** — Exclusão de transações: novo endpoint DELETE `/api/transactions/:id` (204 no sucesso, 404 se não existe, 400 para id inválido via Zod) e botão "Excluir" em cada linha da tabela, com confirmação antes de apagar. A mutação do TanStack Query invalida lista e resumo, então os cards atualizam sozinhos após excluir. Três testes novos no server cobrem os três status.
